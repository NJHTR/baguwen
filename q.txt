什么意思

星期四 13:16

# 一句话先讲明白

Java `HashMap` 里的 `hash()` 函数：**把 key 的 `hashCode()` 的高 16 位 和 低 16 位做异或，目的是扰动，让高位信息也参与到取模寻址里，减少哈希碰撞**。

> 
> 源码（Java8）：

```
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

`h >>> 16`：无符号右移 16 位，**把高 16 位移到低 16 位的位置，高 16 位补 0**
然后 `h ^ (h >>> 16)` 就是：**原 hash 值的低 16 位 ⊕ 原 hash 值的高 16 位**

---

## 1. 先看背景：HashMap 怎么找桶下标

桶下标公式：

```
index = hash & (table.length - 1)
```

table 的长度永远是 2 的幂，比如默认 16：`length-1 = 15 = 0b1111`

👉 **`& 0b1111` 只会保留 hash 值的【低 4 位】，高位直接被丢弃！**
同理，数组长度是 64（`0b111111`），就只用低 6 位。

问题来了：
很多 `hashCode()` 变化都集中在**高位**，低位变化很小甚至几乎不变。
如果直接拿 `hashCode` 去 `& (n-1)`，**高位特征完全浪费，很容易落到同一个桶，碰撞变多**。

举个直观例子：
假设 `hashCode` 是一个 32 位 int：

```
bit31 ~ bit16 【高16位】：变化很大
bit15 ~ bit0   【低16位】：变化很小
```

数组长度很小的时候，只取低几位，高位再怎么变都没用。

---

## 2. `h ^ (h >>> 16)` 做了什么扰动

- `h >>> 16`：把高 16 位挪到低 16 位位置，高 16 位变成 0
```
原h:        [高16位][低16位]
h >>> 16:   [0000...][高16位]
```
- 异或 `^`：**把原来的低 16 位，和挪下来的高 16 位混合在一起**

结果新 hash：

> 
> ✅ **新 hash 的低 16 位 = 原低 16 位 ⊕ 原高 16 位**
> ✅ 新 hash 的高 16 位 = 原高 16 位（因为 `h>>>16` 的高 16 位是 0，异或不变）

后续 `hash & (n-1)` 取下标时，**现在低几位里面已经混入了原来高位的信息**！
高位的差异被 “掺” 到低位里，数组比较小时，高位不同、低位相同的 hashCode，现在算出的下标大概率不一样，减少碰撞。

> 
> 这就叫**扰动（disturbance）**：把高位信息扰动到低位，让低位也带上高位的区分度。

---

## 3. 为什么是异或，不是加、不是与、不是或？

- `&`、`|`：信息丢失严重，区分度变差
- `+`：会产生进位，会改变更多 bit，计算开销更大
- `^`：**相同为 0，不同为 1**，可以简单融合两组 bit，保留差异，计算很快（位运算）

为什么只右移 16 位？
int 正好 32 位，对半切 16+16，刚好把全部高位拿下来和低位混合，是性价比最高的方案。

---

## 4. 举个极简二进制例子（4 位简化理解，代替 32 位）

简化：假设是 4 位数字，我们右移 2 位（对半）

```
h      = 1011 （高2位：10，低2位：11）
h>>>2  = 0010 （高2位移到低2位）
h ^ (h>>>2) = 1001
```

原来低 2 位是 `11`，现在低 2 位变成 `01`，混入了原来高位 `10` 的信息。
如果数组长度是 4（mask=0b11），取低两位，现在高位的差异就生效了。

---

## 5. 补充：Java7 和 Java8 的区别

- Java7：扰动更多次，多次移位异或，扰动更强，但是开销更大
- Java8：只做一次 `h ^ h>>>16`，简化扰动，作者评估：**一次扰动已经足够，性能更好**

> 
> 注意：这个扰动**不能杜绝碰撞**，只是改善「高位变化、低位不动」这种糟糕 hashCode 场景下的碰撞概率。

---

## 总结一句话复盘

> 
> hashCode 是 32 位 int，HashMap 寻址只用到低位；为了不让高位白白浪费，把高 16 位右移到低位，和原来低 16 位异或混合，这个操作就是高低 16 位异或扰动，用来提升低位的随机性，减少哈希碰撞。

什么是table也就是数组对吗？

对，**table 就是 HashMap 底层的那个数组**，全称：`transient Node<K,V>[] table;`

### 1. 先给它定位

```
// HashMap 源码里这个
transient Node<K,V>[] table;
```

- 类型：`Node` 数组，不是直接存 key/value，数组里每一个元素叫**桶（bucket）**
- 数组里的每个 Node：可以是单个节点，也可以是链表 / 红黑树（冲突的时候串起来）
- 数组的长度 n 一定是 **2 的幂**：1、2、4、8、16、32、64…… 默认初始容量 16

> 
> 所以大家口语里说的：
> 
> 
> - table = 哈希表的底层数组
> - 桶 = 数组中的一个下标位置 `table[i]`

### 2. 联系刚才的 hash 扰动、寻址公式

```
index = hash & (table.length - 1);
```

- `table.length` 就是数组长度 n
- `n - 1` 就是掩码 mask，二进制是一串连续的 1，比如 n=16 → mask=15 → `0b1111`
- `hash & mask` = 在数组下标范围内，算出要放到 table 的哪个位置

👉 重点：**寻址是用算出来的 index，去访问 `table[index]` 这个桶**

### 3. 简单流程串一遍

1. key → `hashCode()` 得到 32 位整数 h
2. `h ^ h>>>16` 扰动，得到新 hash（就是刚才说的高低 16 位异或）
3. `hash & (table.length -1)` 算出数组下标 index
4. 去底层数组 `table[index]` 这个桶放 / 找元素

### 4. 容易混淆的点

- table 是数组，但**它只是哈希表的底层载体**；HashMap 整体叫哈希表（Hash Table）
- table 会扩容：元素多了，触发 resize，新建一个更长的 table，然后把所有元素重新算 hash、迁移到新数组

### 举个直观例子

table 长度是 16：

```
table[0] → 桶0
table[1] → 桶1
...
table[15] → 桶15
```

一句话总结：✅ **table 就是 HashMap 底层存放桶的 Node 数组。**

# 核心一句话

它**本质上就是数组**，但它在哈希表里承担的角色是「哈希表的主表」，所以源码变量名取名 `table`；**table 是【角色名字】，数组是【数据结构类型名字】**。

> 
> 类比：
> 柜子（数组这种结构），用来放档案的时候，我们叫它档案表（table）。柜子本身是柜子，但按用途有别的叫法。

---

## 1. 区分两个概念

- **数组（Array）**：是**数据结构类型**。
一块连续内存、按下标访问、固定长度（Java 里普通数组），这是它的类型定义。`Node<K,V>[]` → 这个东西，从类型上讲，就是数组。
- **table**：是 HashMap 源码里给这个数组起的**业务 / 逻辑名字**，代表 **hash table（哈希表）的底层主表**。
完整单词就是 hash table，简写叫 table。

```
transient Node<K,V>[] table;
```

翻译过来：哈希表的底层表。

👉 所以关系：
**table 是一个数组，但不是随便一个数组，是专门用来做哈希桶寻址的数组。**

---

## 2. 那为什么源码不直接叫 `array`，要叫 table？

1. **术语传统：Hash Table**
哈希表（Hash Table）本身就是经典算法名词。它的底层载体就是这个数组，顺理成章叫 table。
如果叫 `array`，只是在说 “这是个数组”，没有表达它是哈希表主体的含义。
2. **它的行为和普通数组不一样，有特殊语义**
普通数组：

- 我 new 一个 `String[] arr`，我就是顺序存、按下标取，下标一般是业务有意义的数字。

而 HashMap 的 table 数组：

- 下标**不是你指定的**，是 hash 值算出来的
- 每个位置叫 bucket（桶），桶里面还可以挂链表 / 红黑树
- 会自动扩容 resize，数据要 rehash 迁移
- 长度强制是 2 的幂，有一套哈希寻址规则

它虽然底层是数组，但它是**哈希表结构里的一张 “索引表”**，承载哈希映射逻辑，所以用 table 更贴合它的角色。

> 
> 如果你叫它数组，只描述了它的形态；叫 table，描述了它在哈希算法里的作用。

3. 行业习惯
很多哈希实现都这么命名：

- Go map 底层的数组也叫 bucket table
- C++ unordered_map 底层也叫 hash table

---

## 3. 举个对比帮你吃透

```
// 普通数组：名字就体现它只是个容器数组
String[] array = new String[16];

// HashMap：这个数组是哈希表的核心，叫 table
transient Node<K,V>[] table;
```

- 问：`table` 是不是数组？✅ 是
- 问：所有数组都叫 table？❌ 不是

> 
> table = **承担哈希桶映射职责的那个数组**

## 4. 容易踩坑的误区

❌ 错误理解：table 和数组是两种不同东西
✅ 正确理解：**table 是扮演哈希主表角色的数组，是数组的一种特定用法**
