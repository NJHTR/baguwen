# Redis 数据结构与底层编码（Data Structures & Encodings）

> 面试权重：5/5　｜　追问深度：**L5（Redis 源码结构体与编码转换）**
> 一句话定位：Redis 快，一半靠内存 + 单线程免锁，另一半靠「为不同规模的数据挑最省内存的编码」。所有「zset 为什么用跳表」「Redis 7 为什么换 listpack」「大 key 为什么危险」的答案，都在这一层。

## L1 一句话答案（10 秒能说出口）

Redis 对外只有 5 种基本类型（string/hash/list/set/zset），内部每种类型都有多种编码：小数据用 SDS、listpack、intset 这类紧凑结构省内存，超过阈值就转成 hashtable、quicklist、skiplist 这类通用结构换性能。**编码对使用者透明，但决定内存占用和命令复杂度。**

## L2 原理层：五种类型 × 编码对照表

### 2.1 类型、编码、阈值一表打尽（Redis 7.x）

| 类型 | 编码 | 转换阈值（配置项） | 转成什么 |
|---|---|---|---|
| string | `int` / `embstr` / `raw` | value 是整数 → int；≤44 字节 → embstr；>44 → raw | raw |
| hash | `listpack` / `hashtable` | `hash-max-listpack-entries 128`、`hash-max-listpack-value 64` | hashtable |
| list | `listpack`（单节点）/ `quicklist`（多节点） | `list-max-listpack-size 128`（负数按内存，如 -2=8KB） | quicklist |
| set | `intset` / `listpack` / `hashtable` | `set-max-intset-entries 512`；`set-max-listpack-entries 128`（7.2+） | hashtable |
| zset | `listpack` / `skiplist` | `zset-max-listpack-entries 128`、`zset-max-listpack-value 64` | skiplist（+dict） |

**注意版本差异**：Redis 7.0 之前 list/hash/zset 的紧凑编码叫 **ziplist**，配置项是 `*-max-ziplist-*`；7.0 起 hash/zset 改用 **listpack**，7.2 起 set 也有 listpack 编码。**转换是单向的**：一旦变成 hashtable/skiplist，删数据也不会自动退回紧凑编码（需要重建/RESTORE）。

### 2.2 各结构的用途与命令

| 类型 | 典型场景 | 常用命令 | 复杂度 |
|---|---|---|---|
| string | 缓存对象、计数器、分布式锁 | `SET/GET/INCR/EXPIRE` | O(1) |
| hash | 存对象字段（用户信息）、购物车 | `HSET/HGET/HGETALL/HINCRBY` | 单字段 O(1)，全量 O(n) |
| list | 消息队列、最新列表 | `LPUSH/RPOP/LRANGE` | 头尾 O(1)，按下标 O(n) |
| set | 去重、共同好友、标签 | `SADD/SISMEMBER/SINTER` | 单元素 O(1) |
| zset | 排行榜、延迟队列、滑动窗口 | `ZADD/ZRANGE/ZSCORE/ZRANGEBYSCORE` | O(log n) |

**选型口诀**：要排序用 zset，要计数用 string（`INCR`），要对象字段用 hash，要队列/栈用 list，要去重/交集用 set。

### 2.3 为什么小数据要"紧凑编码"

- listpack 把多个元素**连续存在一块内存**里，省掉每个元素的 dictEntry/指针开销（Redis 里一个元素动辄 30-50 字节 overhead）。
- 小数据量下 O(n) 扫描完全可接受（128 个元素），换来内存省一个量级。
- 大数据量下必须换 hashtable/skiplist，否则单次操作 O(n) 太慢。

## L3 底层层：几个关键结构体的真实样子

### 3.1 SDS（Simple Dynamic String）

```c
struct sdshdr8 {         // 按字符串长度选 5/8/16/32/64 位头
    uint8_t len;         // 已用长度
    uint8_t alloc;       // 分配长度（不含头和 '\0'）
    unsigned char flags; // 头类型
    char buf[];          // 柔性数组，二进制安全
};
```

**相比 C 字符串**：① `len` 让 `strlen` 变 O(1)；② 二进制安全（可存 `\0`）；③ 预分配减少扩容（`< 1MB` 时翻倍，`>= 1MB` 时每次 +1MB）；④ 惰性释放（缩短字符串不立即 `free`，保留空间复用）。

### 3.2 dict：渐进式 rehash

```c
typedef struct dict {
    dictht ht[2];      // 两个哈希表，rehash 时一个旧一个新
    long rehashidx;    // -1 表示没在 rehash
} dict;

typedef struct dictht {
    dictEntry **table;
    unsigned long size, sizemask, used;
} dictht;
```

- **哈希冲突**：链地址法（每个桶挂链表），不用开放寻址（Redis 要支持删除且插入频繁）。
- **扩容**：`used / size >= 1` 且没有子进程做 BGSAVE/BGREWRITEAOF 时扩容为 `2 * used` 向上取 2 的幂；如果在 fork 子进程期间，负载因子到 5 才强制扩容（避免 COW 内存翻倍）。
- **缩容**：`used / size < 0.1` 时缩容。
- **渐进式**：分配 `ht[1]` 后，`rehashidx` 从 0 开始，每次命令操作顺带迁移一个桶；期间**查找先查 ht[0] 再查 ht[1]，新增只写 ht[1]**，删除两边都查。避免一次性 rehash 卡住单线程。

### 3.3 skiplist：zset 的骨架

```c
typedef struct zskiplistNode {
    sds ele;                 // member
    double score;
    struct zskiplistNode *backward;
    struct zskiplistLevel {
        struct zskiplistNode *forward;
        unsigned long span;  // 跨度，用于 ZRANK 算排名
    } level[];
} zskiplistNode;
```

- **随机层数**：`level = 1; while (random() < 0.25 && level < 32) level++;`，期望层数约 1.33，查找/插入/删除期望 O(log n)。
- **span 的作用**：`ZRANK`/`ZREVRANK` 靠累加 span 得到排名，不用遍历。
- **zset 同时有 dict 和 skiplist**：dict 存 `member -> score`，`ZSCORE` O(1)；skiplist 存排序，范围查询/排名 O(log n)。

### 3.4 listpack、quicklist、intset

- **listpack**：一块连续内存，每个 entry 有自身长度编码 + backlen（从尾往前遍历用）。**相比 ziplist 核心改进：去掉了 prevlen 字段，避免"连锁更新"**（ziplist 前一个 entry 长度变化可能级联改后面所有 entry）。
- **quicklist**：`list` 的默认编码，本质是**双向链表 + 每节点一个 listpack**，兼顾插入性能和内存；节点过大时 listpack 拆分。
- **intset**：`encoding(2/4/8B) + length + contents[]`，元素**有序不重复**，查找二分；插入更大的数会**升级**（2→4→8 字节），升级不可逆。

## L4 追问树（面试官一路往下问，你能撑到第几层？）

> 规则：从上往下问。**第 1-3 层是应届生必备，第 4-6 层是拉开差距，第 7 层以后是"能答出来就是加分"。**

### 第 1 层｜Redis 5 种基本类型，底层分别是什么？
**答**：string 是 SDS；hash 小数据 listpack、大数据 hashtable；list 是 listpack/quicklist；set 是 intset/listpack/hashtable；zset 是 listpack/skiplist（配 dict）。

### 第 2 层｜为什么 string 的 embstr 阈值是 44 字节？
**答**：embstr 把 `redisObject` 和 SDS 分配在同一块内存里（一次 malloc）。`redisObject` 16B + `sdshdr8` 头 3B + 结尾 `\0` 1B = 20B，而 jemalloc 的 64B 内存块装下 44 字节字符串正好（64-20=44）。超过 44 字节要单独分配 SDS，变成 raw。

### 第 3 层｜zset 为什么用跳表，不用红黑树/平衡树？
**答**：① 跳表范围查询天然友好（底层链表顺序遍历），红黑树范围查询要中序回溯；② 跳表实现简单、无旋转，插入删除不用再平衡；③ 内存上跳表平均 1.33 层、可控。zset 还需要按 member 取 score，所以再配一个 dict。

### 第 4 层｜zset 为什么跳表和 dict 都要？
**答**：dict 负责 `ZSCORE`（按 member 查 score）O(1)；跳表负责排序和范围（`ZRANGE`/`ZRANGEBYSCORE`/`ZRANK`）O(log n)。两个结构共享同一份 member/score 数据（不是两份拷贝）。

### 第 5 层｜跳表层数怎么随机？期望多少层？最高多少？
**答**：每层以 1/4 概率继续上升（`ZSKIPLIST_P=0.25`），最大 32 层。期望总层数约 1.33 层/节点，n 个节点的期望高度 O(log n)，所以查找/插入 O(log n)。层数上限 32 是硬编码 `ZSKIPLIST_MAXLEVEL`。

### 第 6 层｜渐进式 rehash 具体怎么做？期间读写的规则？
**答**：`ht[2]` 里 `ht[1]` 分配为 2 的幂，`rehashidx=0`；每次命令顺带迁移 `ht[0]` 的一个桶到 `ht[1]`；查找先 ht[0] 后 ht[1]；新增只写 ht[1]；删除两边都查。全部搬完交换 ht[0]/ht[1]，`rehashidx=-1`。这样把 O(n) 的迁移摊到每次操作。

### 第 7 层｜dict 什么时候扩容/缩容？为什么 fork 期间要放宽？
**答**：负载因子 `used/size >= 1` 扩容（fork 子进程期间要 >= 5 才强制扩容，因为写时复制会放大内存）；`< 0.1` 缩容。缩放都是 2 的幂次，扩容为 `used*2` 向上取整。

### 第 8 层｜listpack 和 ziplist 有什么区别？为什么 Redis 7 要换？
**答**：ziplist 每个 entry 存 prevlen，前一个 entry 变长会级联改后面所有 entry（连锁更新，最坏 O(n²)）；listpack 每个 entry 只存自身长度 + backlen，从尾往前也能遍历，杜绝连锁更新。所以 7.0 起 hash/zset 换 listpack。

### 第 9 层｜intset 什么时候升级？升级后能降级吗？
**答**：插入元素超出当前编码范围（1126 超 2B、32767 超 4B）就升级到 8 字节，需要重新分配内存并搬移；升级单向不可逆，因为降级要扫描判断，成本高。元素超过 `set-max-intset-entries`（默认 512）或出现非整数，转 hashtable/listpack。

### 第 10 层｜大 key 有什么危害？怎么发现和处理？
**答**：危害：单线程下 `DEL` 大 key、`HGETALL`、`SMEMBERS` 会阻塞；网络带宽被打满；集群槽位倾斜。发现：`redis-cli --bigkeys`、`MEMORY USAGE key`、`SCAN` 采样。处理：`UNLINK` 异步删除、`HSCAN` 分批、业务上拆 key（hash 分桶）、设置合理 TTL。

### 第 11 层｜一个 `HSET` 什么时候从 listpack 变成 hashtable？能说出配置吗？
**答**：`hash-max-listpack-entries`（元素数，默认 128）或 `hash-max-listpack-value`（单个 value 长度，默认 64 字节）任一超限就转 hashtable。转完不可逆。zset 同理（`zset-max-listpack-entries/value`），set 用 `set-max-intset-entries`/`set-max-listpack-entries`。

### 第 12 层（终局）｜Redis 源码里这些结构在哪个文件？
**答**：`sds.c`（`sdsMakeRoomFor` 扩容策略）、`dict.c`（`dictExpand`、`dictRehash` 渐进迁移）、`t_zset.c`（`zslInsert` 插跳表、`zslRandomLevel` 随机层数）、`listpack.c`（`lpAppend`、`lpEncodeBacklen`）、`intset.c`（`intsetUpgradeAndAdd`）、`object.c`（`tryObjectEncoding` 决定编码）。

## L5 名词拆解表（"每个名词都拆开"）

| 名词 | 是什么 | 为什么存在 | 面试追问点 |
|---|---|---|---|
| SDS | 带长度头的动态字符串 | O(1) 长度、二进制安全、预分配 | 与 C 字符串的区别 |
| robj | Redis 对象，含 type + encoding | 对上层屏蔽编码差异 | encoding 位与共享对象 |
| int | string 存整数的编码 | 省内存，可直接 INCR | 范围限制 |
| embstr | redisObject 与 SDS 同块分配 | 一次 malloc，小字符串省内存 | 为什么是 44 字节 |
| raw | 独立分配的 SDS | 大字符串 | 44 字节边界 |
| listpack | 连续内存紧凑列表 | 省 overhead、无连锁更新 | 与 ziplist 区别 |
| ziplist | 旧版紧凑列表 | 历史实现 | prevlen 连锁更新 |
| quicklist | 双向链表 + listpack 节点 | 兼顾内存与插入性能 | 节点大小配置 |
| intset | 有序整数集合 | 整数集合省内存 | 升级不可逆 |
| hashtable | dict 编码 | O(1) 读写 | 渐进式 rehash |
| skiplist | 多层链表 + span | O(log n) 有序结构 | 随机层数、span 排名 |
| dict | 哈希表结构 | 支撑 hash/set/zset 索引 | 两个 ht、rehashidx |
| rehash | 扩容时逐步迁移桶 | 避免单次 O(n) 阻塞 | 读写规则 |
| 大 key | 单 key 元素过多/值过大 | 阻塞主线程、槽倾斜 | 发现与 UNLINK |

## 代码验证（本机 redis-cli 逐条跑，观察 OBJECT ENCODING）

> 版本提示：Redis 6 及以前没有 listpack，hash/zset 会显示 `ziplist`、list 显示 `quicklist`（或 3.x 的 `ziplist`），配置名为 `*-max-ziplist-*`；下面的注释按 Redis 7.x 写，6.x 上编码名不同属正常。

```bash
# 1. string 三种编码
redis-cli SET s1 123            ; redis-cli OBJECT ENCODING s1   # int
redis-cli SET s2 "hello"        ; redis-cli OBJECT ENCODING s2   # embstr（<=44B）
redis-cli SET s3 "$(printf 'a%.0s' {1..50})"; redis-cli OBJECT ENCODING s3  # raw

# 2. hash 编码切换
redis-cli HSET user:1 name tom age 20 ; redis-cli OBJECT ENCODING user:1  # listpack
redis-cli HSET user:2 name "$(printf 'a%.0s' {1..65})" ; redis-cli OBJECT ENCODING user:2  # hashtable（value>64B）

# 3. set 编码
redis-cli SADD tags 1 2 3        ; redis-cli OBJECT ENCODING tags   # intset
redis-cli SADD tags abc          ; redis-cli OBJECT ENCODING tags   # listpack/hashtable

# 4. zset 编码：128 个成员及以内 listpack，超过 128 转 skiplist
redis-cli ZADD rank 89 tom 95 jerry ; redis-cli OBJECT ENCODING rank  # listpack
# 批量插入 200 个成员后：
redis-cli ZADD rank $(for i in $(seq 1 200); do echo "$i m$i"; done) ; redis-cli OBJECT ENCODING rank

# 5. 查看阈值配置
redis-cli CONFIG GET 'hash-max-*'
redis-cli CONFIG GET 'zset-max-*'
redis-cli CONFIG GET list-max-listpack-size
redis-cli CONFIG GET set-max-intset-entries

# 6. 内存与排名
redis-cli MEMORY USAGE rank
redis-cli ZRANK rank jerry        # 靠 span 累加，O(log n)
redis-cli ZRANGE rank 0 2 WITHSCORES

# 7. 大 key 扫描（生产低峰期跑）
redis-cli --bigkeys
```

```java
// Jedis 片段：zset 排行榜 + hash 对象缓存
try (Jedis jedis = new Jedis("127.0.0.1", 6379)) {
    jedis.zadd("rank", 95.0, "jerry");
    jedis.zadd("rank", 89.0, "tom");
    jedis.zrangeWithScores("rank", 0, 9)
         .forEach(e -> System.out.println(e.getElement() + "=" + e.getScore()));
    jedis.hset("user:1", java.util.Map.of("name", "tom", "age", "20"));
    System.out.println(jedis.hgetAll("user:1"));
}
```

## 高频错误（面试官最爱抓的）

| 错误说法 | 正确说法 |
|---|---|
| 「Redis 只有 5 种编码」 | 5 种基础类型，底层 11+ 种编码 |
| 「zset 底层是红黑树」 | 跳表 + dict（listpack 小数据时） |
| 「编码变了会自己变回来」 | 转换单向，重建/RESTORE 才回紧凑编码 |
| 「listpack 就是 ziplist 改名」 | listpack 去掉 prevlen，解决连锁更新 |
| 「跳表是 O(n) 查找」 | 期望 O(log n)，层数随机但高度 O(log n) |
| 「dict 扩容是一次性 rehash」 | 渐进式，每次操作迁移一个桶 |
| 「intset 可以降级」 | 升级不可逆 |
| 「Redis 7 的 list 还是 ziplist」 | 7.0 起 list 节点是 listpack，quicklist 包装 |
