# 闭包（Closure）

> 面试权重：5/5　｜　追问深度：**L5（V8 Context 分配 + GC 可达性）**
> 一句话定位：函数 + 定义时词法环境的组合。闭包不是语法糖，是作用域链的必然结果；它决定了变量能活多久，也解释了 React hooks 为什么总拿到「旧值」。

**本文件用法**：L1-L2 是能张口就答的版本，L3 开始才是面试官真正想听的。**每读完一层，试着用「如果我是面试官，下一问是什么」反问自己。**

## L1 一句话答案（10 秒能说出口）

闭包是**函数与其定义时词法环境的组合**：内层函数引用了外层变量，并在外层函数返回后依然能访问这些变量。变量不会被销毁，直到引用它的函数对象变得不可达。

---

## L2 原理层：词法作用域与闭包的形成

```
全局环境
└── createCounter 执行上下文（调用结束已出栈）
    └── 词法环境 { count: 0 }
        └── 返回的对象 { inc, get }
             └── 两个函数对象的 [[Environment]] ──► 上面的词法环境
```

**闭包形成的三个条件**（缺一不可）：
1. 存在内层函数；
2. 内层函数引用了外层函数的变量；
3. 内层函数「逃逸」出外层作用域（被返回、被回调保存、挂到对象上）。

**常见应用**：
- 私有变量 / 模块模式：只暴露方法，状态藏在闭包里。
- 防抖、节流、柯里化、`once` 函数。
- 缓存（memoize）：闭包持有 cache。
- React 函数组件：每次渲染都是一个新闭包，捕获这次渲染的 props/state。

```js
function createCounter() {
  let count = 0 // 外部无法直接访问
  return {
    inc: () => ++count,
    get: () => count,
  }
}
const counter = createCounter()
counter.inc(); counter.inc()
console.log(counter.get()) // 2
```

**循环经典题**：

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0) // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j), 0) // 0 1 2
```

`var` 只有一个共享绑定，循环结束时 `i === 3`；`let` 每轮迭代创建新的词法环境绑定，回调各自捕获一份。

## L3 底层层：变量到底存在哪，什么时候被回收

### 3.1 V8 的 `Context`：闭包捕获的是槽位，不是值

- V8 里每个函数对象有一个 `context_` 指针（对应规范里的 `[[Environment]]`）；
- 函数被编译时，`ScopeInfo` 会记录「哪些变量需要被内层函数访问」。需要被捕获的变量**从栈提升到堆上的 `Context` 对象**（context-allocated），用槽位索引访问；
- 所以闭包捕获的是 **Context 里的槽位**（活引用），不是值的拷贝。多个闭包共享同一个 Context 时，看到的是同一份状态；
- 内层函数返回后，局部栈帧虽然出栈了，但 Context 被函数对象的 `context_` 指着，因此留在堆上。

### 3.2 闭包什么时候被回收：可达性决定一切

GC 从根（全局对象、调用栈、活动句柄）出发做可达性分析：

```
根 → 事件监听器/定时器/全局变量 → 闭包函数对象 → Context → 变量 → 大对象
```

只要这条链上任何一环可达，Context 和变量就不会被回收。**闭包本身不是内存泄漏，泄漏是"不再需要却仍然可达"**：

| 泄漏场景 | 为什么可达 | 修法 |
|---|---|---|
| `setInterval` 里引用大数组，组件卸载没清 | 定时器是全局根 | 保存 id，卸载时 `clearInterval` |
| `window.addEventListener` 的回调用闭包引用组件状态 | 全局事件源持有回调 | 卸载时 `removeEventListener` |
| 模块级缓存 `Map` 无限增长 | 模块作用域永久可达 | `WeakMap` / 加 LRU 上限 |
| 闭包持有已移除的 DOM 节点 | 变量仍指向节点 | 置 `null` 或缩短闭包生命周期 |

### 3.3 React hooks 的 stale closure（项目高频）

```jsx
function Counter() {
  const [count, setCount] = useState(0)
  useEffect(() => {
    const timer = setInterval(() => {
      console.log(count) // 永远打印 0：捕获的是首次渲染的闭包
    }, 1000)
    return () => clearInterval(timer)
  }, []) // 空依赖：effect 只执行一次
}
```

函数组件每次渲染都是新闭包，`useEffect` 里捕获的是**那一次渲染的 `count` 快照**。三种解法：
1. 依赖数组写 `[count]`，effect 重建（注意清理）；
2. 用函数式更新 `setCount((c) => c + 1)`，不读外部 `count`；
3. 用 `useRef` 存最新值，或 React 19.2 的 `useEffectEvent`（事件回调读取最新 props/state，不参与依赖）。

## L4 追问树（面试官一路往下问，你能撑到第几层？）

> 规则：从上往下问。**第 1-3 层必备，第 4-6 层拉开差距，第 7 层以后加分。**

### 第 1 层｜闭包是什么？
**答**：函数和它定义时词法环境的组合；内层函数引用外层变量并在外层返回后仍能访问，变量因此不会被回收。

### 第 2 层｜闭包和词法作用域的关系？
**答**：闭包是词法作用域的产物。变量属于定义位置所在的环境，函数对象通过 `[[Environment]]` 记住那个环境；调用位置不影响查找结果。

### 第 3 层｜为什么 `var` 循环打印 3 个 3，`let` 就正常？
**答**：`var` 全循环共享一个绑定，同步循环结束时已是 3，回调执行时读到的都是 3；`let` 每次迭代创建新绑定并拷贝当前值，每个回调捕获各自的绑定。

### 第 4 层｜IIFE 为什么也能修好？
**答**：IIFE 立即执行，把当前的 `i` 作为参数传入新函数的词法环境，等于给每轮创建独立变量；本质和 `let` 一样是「每轮一份」。

### 第 5 层｜闭包会造成内存泄漏吗？
**答**：不会自动泄漏。闭包只是延长变量生命周期；只有外部还持有闭包、但业务上已不需要时才算泄漏，常见于定时器、全局监听、无上限缓存。

### 第 6 层｜闭包变量存在栈还是堆？V8 怎么决定？
**答**：默认在栈上；如果被内层函数引用（逃逸），V8 根据 `ScopeInfo` 把它提升到堆上的 `Context`，闭包通过槽位索引访问。所以「闭包变量都在堆上」是过度简化。

### 第 7 层｜React 里为什么会 stale closure？
**答**：函数组件每次渲染生成新闭包；`useEffect`/`useCallback` 捕获的是创建它们那次渲染的 props/state 快照，依赖数组没更新时回调不会重建，读到的就是旧值。

### 第 8 层｜怎么解决 stale closure？各自代价是什么？
**答**：① 补全依赖数组，正确但容易触发多余重建；② 函数式更新 `setState(prev => ...)`，适合计数/累加；③ `useRef` 保存最新值，读 ref 不触发重建，但绕开了响应式、要自己保证同步；④ React 19.2 的 `useEffectEvent` 专门解决「读最新值但不进依赖」，是最干净的方案。

### 第 9 层｜防抖/节流为什么离不开闭包？
**答**：需要跨调用保存 `timer`/`lastTime` 状态，又不想污染全局——闭包提供私有可变状态。注意 `this` 和参数要用 `apply` 转发，否则 `obj.method = debounce(obj.method)` 后 this 会丢。

### 第 10 层（终局）｜一次闭包从创建到回收，V8 内部发生了什么？
**答**：编译期 `ScopeInfo` 标记 context-allocated 变量；调用时创建 `Context`，变量搬进去；返回的内层函数对象 `context_` 指向它。执行期所有访问走「Context 槽位索引」。GC 时从根做可达性分析：只要函数对象（或它挂载的监听器/定时器）可达，Context 就不可回收；引用链断开后，Scavenge/Mark-Compact 才会回收，这就是「闭包导致内存涨」的完整解释链。

## L5 名词拆解表（"每个名词都拆开"）

| 名词 | 是什么 | 为什么存在 | 面试追问点 |
|---|---|---|---|
| 词法环境（Lexical Environment） | 变量名 → 值的映射 + 外层引用 | 支撑作用域链查找 | 变量环境 vs 词法环境区别 |
| 环境记录（Environment Record） | 存储声明的结构 | 区分 var/let/函数声明 | 声明式 vs 对象式环境记录 |
| 作用域链 | 环境逐层向外的链表 | 内层找不到往外找 | 链长与查找性能 |
| 执行上下文 | 函数调用时的运行环境 | 管理 this/变量/作用域 | 调用栈溢出 |
| `[[Environment]]` | 函数对象的内部槽 | 记住定义时的环境 | 与调用位置无关 |
| Context（V8） | 堆上的变量存储对象 | 让闭包跨栈帧存活 | 什么时候创建、槽位索引 |
| ScopeInfo | 编译期的作用域元数据 | 告诉运行时哪些变量要进 Context | context-allocated |
| context-allocated | 变量被分配进堆 Context | 内层函数可能访问 | 为什么不是所有变量都堆分配 |
| 逃逸（escape） | 函数/变量离开定义作用域仍存活 | 闭包形成条件 | 逃逸分析与 GC |
| stale closure | 回调捕获了旧渲染快照 | 函数式渲染的副作用 | React 依赖数组 |
| IIFE | 立即执行函数表达式 | 创建独立作用域 | var 循环修复 |
| 可达性（reachability） | 从根能否访问到对象 | GC 回收判据 | WeakMap 为何能自动释放 |
| `WeakMap` | 键弱引用的字典 | 缓存不阻止回收 | 与 Map 的区别 |

## 代码验证（打开浏览器控制台逐条跑，验证理解）

```js
// 1. 闭包共享同一个环境
function make() {
  let n = 0
  return [() => ++n, () => n]
}
const [inc, read] = make()
inc(); inc()
console.log(read()) // 2（两个函数共享同一 Context）

// 2. var 循环 vs let 循环 vs IIFE
for (var i = 0; i < 3; i++) setTimeout(() => console.log('var', i), 0) // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log('let', j), 0) // 0 1 2
for (var k = 0; k < 3; k++) {
  ;(function (v) { setTimeout(() => console.log('iife', v), 0) })(k) // 0 1 2
}

// 3. 模拟 React stale closure：回调捕获的是创建时的快照
function useSnapshot(value) {
  return () => value // 返回的回调永远读创建时的 value
}
const show = useSnapshot(0)
console.log(show()) // 0
// React 里 state 更新后如果回调没重建，读到的仍是旧值

// 4. 防抖：闭包保存 timer（1 秒内连续调用只执行最后一次）
function debounce(fn, wait) {
  let timer = null
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), wait)
  }
}
let calls = 0
const run = debounce(() => { calls++; console.log('执行一次，calls =', calls) }, 100)
run(); run(); run()
// 预期：100ms 后只打印一次 "执行一次，calls = 1"

// 5. 断开引用后变量才可回收
let big = null
function hold() {
  const arr = new Array(1e6).fill('x')
  big = () => arr.length // 闭包持有大数组
}
hold()
console.log(big()) // 1000000
big = null // 断开后，arr 和闭包都可被回收（下一次 GC）
```

## 高频错误（面试官最爱抓的）

| 错误说法 | 正确说法 |
|---|---|
| 「闭包一定会内存泄漏」 | 只是延长生命周期，不再可达才回收 |
| 「闭包捕获的是变量的值」 | 捕获的是词法环境的绑定/槽位，是活引用 |
| 「`let` 能修好 `for` 循环是因为闭包被禁用」 | 是每轮创建了新绑定 |
| 「所有闭包变量都在堆上」 | 只有被内层函数引用的才 context-allocated |
| 「React 的 stale closure 用 `useMemo` 能解决」 | 用依赖数组/函数式更新/useRef/useEffectEvent |
| 「闭包就是匿名函数」 | 具名函数、箭头函数都能形成闭包 |
