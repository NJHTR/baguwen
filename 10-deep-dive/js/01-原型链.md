# 原型链（Prototype Chain）

> 面试权重：5/5　｜　追问深度：**L5（V8 引擎内部）**
> 一句话定位：JS 的继承与属性查找机制。所有「为什么这个对象能调用那个方法」「为什么 instanceof 不准」的问题，答案都在这里。

**本文件用法**：从 L1 往下读，每读完一层，合上书自问自答。**停在答不出的那一层，就是你的真实水平线。**
[返回深度追问索引](../00-索引.md)

## L1 一句话答案（10 秒能说出口）

每个对象都有一个内部槽 `[[Prototype]]` 指向另一个对象（或 `null`）。访问属性时，先查自身，查不到就顺着 `[[Prototype]]` 往上找，直到找到或到达 `null` 为止——这条链就是原型链。

---

## L2 原理层：`prototype` / `__proto__` / `constructor` 三者关系

```
函数对象 fn
├── fn.prototype  ────────►  原型对象 P
│                              ├── P.constructor ──► fn（指回去）
│                              └── P.__proto__ ───► Object.prototype
└── fn.__proto__ ─────────►  Function.prototype

实例 o = new fn()
└── o.__proto__ ──────────►  fn.prototype（= P）
```

**关键区分**：

| 写法 | 存在于 | 含义 |
|---|---|---|
| `fn.prototype` | 只有**函数**（除了箭头函数/方法简写等）才有 | 手工挂的「共用属性仓库」，`new` 时给实例当原型 |
| `o.__proto__`（= `Object.getPrototypeOf(o)`） | 所有对象都有（通过 `Object.prototype` 上的 accessor 暴露） | 运行时真正的原型指针 |
| `P.constructor` | 原型对象上 | 反向指回构造函数，**可被篡改，依赖它做类型判断不可靠** |

**`new` 的四步**（必须能背）：
1. 创建新对象 `{}`
2. 把新对象的 `[[Prototype]]` 指向 `Fn.prototype`
3. 以新对象为 `this` 执行 `Fn`
4. **如果构造函数返回的是对象，就返回它；否则返回新对象**（这条是追问高发区）

**属性查找路径**：`自有属性 → [[Prototype]] → ... → Object.prototype → null`。所以：
- `o.toString` 能找到，是因为 `Object.prototype.toString` 在链尾
- `hasOwnProperty` 只查自身，`in` 会查整条链
- 创建时用 `Object.create(null)` 得到「无原型」对象，不能调用任何 Object 方法，适合做纯字典（避免 `obj["toString"]` 污染）

## L3 底层层：V8 到底把它存在哪

### 3.1 对象的内部结构（V8 的 `JSObject`）

```
JSObject
├── map_            ──► Map（隐藏类 / Hidden Class）：描述「形状」+ 指向 prototype
├── properties_     ──► 属性存储（in-object slots 或 PropertyArray）
├── elements_       ──► 索引属性存储（数组元素）
└── in-object 槽位  ──► 前若干个属性直接内联在对象体里
```

- **对象本身不存 `__proto__` 字段**。原型指针存在 `map_` 里（`Map::prototype`），所以在 V8 里「改原型」= 改隐藏类指针，这也是 `Object.setPrototypeOf` 慢的根因。
- 属性访问靠**隐藏类 + 偏移量**：同一个构造函数创建的多个对象共享同一个 `Map`，属性偏移固定，JIT 可以直接编译成「对象地址 + 固定偏移」的一次内存读。
- 原型链上的属性不走偏移量，而是走**原型链遍历 + Inline Cache（IC）**。

### 3.2 Inline Cache：V8 让原型查找几乎不花钱

调用 `o.foo()` 时，IC 记住「上次 `o` 的 Map 是什么、`foo` 在哪个原型上、偏移是多少」：

| IC 状态 | 触发条件 | 性能 |
|---|---|---|
| uninitialized | 第一次执行 | 慢（走完整查找） |
| monomorphic（单态） | 只见过 1 种 Map | 极快（直接命中偏移） |
| polymorphic（多态） | 见过 2-4 种 Map | 较快（按 Map 线性比对） |
| megamorphic（超态） | >4 种 Map | 放弃缓存，回到哈希查找 |

**这解释了：** 为什么对象「形状要稳定」（同构造函数、同字段顺序、不要运行时 `delete`/`add` 属性）——每变一次形状，V8 就新建一个 Map，IC 退化，性能掉一个量级。

### 3.3 `__proto__` 的本质

`__proto__` **不是对象的普通属性**，而是 `Object.prototype` 上定义的一对访问器：

```js
Object.getOwnPropertyDescriptor(Object.prototype, '__proto__')
// { get: [Function: get __proto__], set: [Function: set __proto__], enumerable: false, configurable: true }
```

所以：
- `obj.hasOwnProperty('__proto__')` → `false`
- `obj.__proto__` 实际执行了 getter，等价于 `Object.getPrototypeOf(obj)`
- `Object.create(null)` 出来的对象**没有** `__proto__`，访问是 `undefined`

## L4 追问树（面试官一路往下问，你能撑到第几层？）

> 规则：从上往下问。**第 1-3 层是应届生必备，第 4-6 层是拉开差距，第 7 层以后是"能答出来就是加分"。**

### 第 1 层｜`prototype` 和 `__proto__` 区别？
**答**：`prototype` 是函数才有的属性，是给 `new` 出来的实例当原型用的「仓库」；`__proto__` 是所有对象都有的原型指针（本质是访问器）。一句话：`fn.prototype` 是给别人的，`o.__proto__` 是看自己指向谁。

### 第 2 层｜为什么箭头函数没有 `prototype`？
**答**：`prototype` 由内部 `[[Construct]]` 能力派生，箭头函数没有 `[[Construct]]`（不能被 `new`），所以没有 `prototype` 属性。同理，方法简写、`async` 函数、生成器函数也没有 `[[Construct]]`。

### 第 3 层｜`new` 具体做了什么？构造函数返回对象会怎样？
**答**：四步（见 L2）。如果构造函数 `return` 的是**对象**（含数组、函数、`null` 外的对象），会覆盖默认返回；如果返回**基本类型**（数字、字符串、`undefined`），被忽略，仍返回新对象。

### 第 4 层｜`instanceof` 怎么实现？为什么可能不准？
**答**：`a instanceof B` 沿 `a` 的原型链查找，看是否命中 `B.prototype`。不准的三种情况：
1. 跨 realm（iframe 里 `Array` 和主窗口 `Array` 不是同一个构造函数）
2. `Symbol.hasInstance` 自定义了行为
3. 原型被中途替换（`B.prototype = {}` 后，老实例不再 instanceof B）

```js
// instanceof 的等价实现
function myInstanceof(obj, Ctor) {
  if (typeof obj !== 'object' || obj === null) return false
  const target = Ctor.prototype
  let proto = Object.getPrototypeOf(obj)
  while (proto) {
    if (proto === target) return true
    proto = Object.getPrototypeOf(proto)
  }
  return false
}
```

### 第 5 层｜修改 `Fn.prototype` 会影响已经创建的对象吗？
**答**：**分两种，很多人答错**：
- 改 `Fn.prototype` **上的属性**（`Fn.prototype.x = 1`）：已创建的实例立即可见（因为共享同一个原型对象）
- 把 `Fn.prototype` **整体替换**（`Fn.prototype = { y: 2 }`）：已创建实例的 `[[Prototype]]` 仍指向**老对象**，看不到 `y`

### 第 6 层｜为什么 `Object.setPrototypeOf` 性能很差？
**答**：因为它要修改对象 `map_` 上的 prototype 指针，同时让所有以该 Map 为形状的 IC 失效、可能触发隐藏类迁移和 deopt。V8 官方建议：**在对象创建时确定原型**（`Object.create(proto)`），不要创建后再改。

### 第 7 层｜原型链查找是 O(n) 吗？V8 怎么优化？
**答**：逻辑上是 O(链长)。V8 用两招把常数降到极小：
1. **Inline Cache**：命中后直接拿偏移量，不遍历
2. **原型链缩短**：`Object.prototype` 位于链尾，常见方法查找基本 1-2 跳
另外，V8 会把「原型链长度」纳入 Map 的校验（prototype validity），原型一变，缓存的 IC 失效。

### 第 8 层｜`typeof null === 'object'` 是为什么？
**答**：历史 bug。JS 最初的实现用 32 bit 标记类型，低位 `000` 表示 object，而 `null` 被表示成全 0 指针，于是 `typeof` 判成了 object。修复会破坏存量代码，所以留到现在。

### 第 9 层｜`class` 继承底层是原型链吗？`super` 怎么实现？
**答**：是。`class B extends A` 让 `B.prototype.__proto__ === A.prototype`，同时 `B.__proto__ === A`（静态属性继承），两条链。`super()` 在规范里是 `[[Construct]]` 调用父构造，`super.method()` 走父原型上的方法并把 `this` 绑为当前实例——和手写原型链继承等价，只是多了 TDZ、不可枚举、必须 `super()` 先于 `this` 等约束。

### 第 10 层（终局）｜V8 里一次 `o.foo` 到底发生了什么？
**答**：① 取 `o.map_`；② 在 Map 的 DescriptorArray 里查 `foo`，命中则按偏移读 in-object/out-object 存储；③ 未命中则查 `map_.prototype` 继续；④ IC 记录本次 (Map, 偏移) 以便下次直接命中；⑤ 整个链都没找到返回 `undefined`（对 `[[Get]]`）或走 `[[Set]]` 的严格/非严格语义。

## L5 名词拆解表（"每个名词都拆开"）

| 名词 | 是什么 | 为什么存在 | 面试追问点 |
|---|---|---|---|
| `[[Prototype]]` | 规范定义的内部槽，指向原型对象 | 属性查找与继承的载体 | 不可直接访问，只能经 `getPrototypeOf` |
| `prototype` | 函数对象的普通属性 | `new` 时用作实例的原型 | 箭头函数为何没有 |
| `__proto__` | `Object.prototype` 上的访问器 | 历史遗留 + 便利访问 | 不是自有属性；`Object.create(null)` 无 |
| `constructor` | 原型对象上的属性指回构造函数 | 便于反查类型 | 可篡改，别用于类型判断 |
| `[[Get]]` / `[[Set]]` | 属性读写内部方法 | 定义查找/赋值的完整语义 | `[[Set]]` 不会修改原型上的值而是创建自有属性 |
| Hidden Class / Map | V8 描述对象形状的元数据 | 让属性访问变成固定偏移 | 加删属性导致 Map 迁移、IC 退化 |
| Inline Cache | 缓存「某 Map 下属性在哪」 | 让原型查找接近免费 | 单态/多态/超态、megamorphic |
| Prototype Validity Cell | 校验原型链是否被改过 | 改原型后失效缓存 | `setPrototypeOf` 为何慢 |
| `Symbol.hasInstance` | 自定义 `instanceof` 的钩子 | 让 instanceof 可被重定义 | 类库常用它做鸭子类型判断 |
| realm | 独立的 JS 执行环境（如 iframe） | 隔离全局对象 | 跨 realm 的 instanceof/`Array.isArray` 差异 |
| deopt | 优化代码回退到未优化版本 | 类型假设失效时的安全网 | 形状不稳定、原型变更导致 |

## 代码验证（打开浏览器控制台逐条跑，验证理解）

```js
// 1. prototype vs __proto__
function F() {}
const f = new F()
console.log(f.__proto__ === F.prototype)        // true
console.log(F.prototype.__proto__ === Object.prototype) // true
console.log(Object.getPrototypeOf(f) === F.prototype)   // true
console.log(f.hasOwnProperty('__proto__'))      // false（是 accessor）

// 2. 改原型属性 vs 换原型对象
function G() {}
const g1 = new G()
G.prototype.x = 1
console.log(g1.x)          // 1（改属性，实例可见）
G.prototype = { y: 2 }
const g2 = new G()
console.log(g1.y, g2.y)    // undefined 2（g1 仍指向老原型）

// 3. 构造函数返回对象
function H() { this.a = 1; return { b: 2 } }
console.log(new H())       // { b: 2 }（对象返回覆盖）
function I() { this.a = 1; return 42 }
console.log(new I())       // { a: 1 }（基本类型被忽略）

// 4. Object.create(null) 无原型
const dict = Object.create(null)
console.log(dict.toString) // undefined
console.log('__proto__' in dict) // false

// 5. 跨 realm 判断（在页面里 iframe 测试）
// const iframeArr = iframe.contentWindow.Array.from([])
// iframeArr instanceof Array  // false
// Array.isArray(iframeArr)    // true（这题的标准答案是"用 Array.isArray"）
```

## 高频错误（面试官最爱抓的）

| 错误说法 | 正确说法 |
|---|---|
| 「原型链查找是 O(1)」 | 逻辑 O(n)，V8 靠 IC 优化到近似常数 |
| 「`__proto__` 就是 `prototype`」 | 一个是对象上的指针，一个是函数上的属性 |
| 「改 `Fn.prototype` 会影响所有实例」 | 只有改**属性**会影响；整体**替换**不影响已创建实例 |
| 「instanceof 靠 constructor 判断」 | 靠原型链，`constructor` 可篡改 |
| 「箭头函数也有 prototype，只是空的」 | 箭头函数根本没有 `prototype` |
| 「`Object.create(null)` 和 `{}` 一样」 | 前者没有原型链，不能调 Object 方法 |
