# 深度追问索引（Deep Dive）

> 目的：一个知识点一个文件，从「一句话答案」一路追问到「引擎 / 内核 / 源码」层。
> 口径：**以后端为主**，前端只保留全栈面试确实会被问到的 9 个点。
> 规模：56 个知识点，每篇 200-290 行，追问树 10-15 层。

---

## 一、为什么单独开这一层

[01-js](../01-js/JS核心八股.md)、[03-java](../03-java/Java基础与并发.md) 这些是**广度覆盖**：一个文件塞二十个知识点，每个能答六十秒。

但真实面试会这样打断：

```
面试官：说说 HashMap 的扩容。
我：容量翻倍，元素重新散列。
面试官：为什么容量必须是 2 的幂？扩容时元素怎么分配？
我：（卡住）
```

**广度会了、深度没有**，是本目录要解决的问题。每个知识点单独一个文件，内部按 L1 到 L5 分层，每层都准备好下一层追问和答案。

---

## 二、深度分层规范（所有文件统一）

| 层级 | 内容 | 对应面试场景 |
|---|---|---|
| L1 | 一句话答案（十秒） | 开场第一问 |
| L2 | 原理层（机制、流程、图示、代码） | 「展开讲讲」 |
| L3 | 底层层（HotSpot / InnoDB / Redis / Linux / 协议字段） | 「底层怎么做的」 |
| L4 | 追问树（十层以上连续追问与答案，末层为终局） | 「再往下呢」 |
| L5 | 名词拆解表（是什么 / 为什么存在 / 追问点） | 把名词逐个拆开 |
| 附 | 代码验证、高频错误、关联文件、自测标准 | 自查与串联 |

> 自测法：从 L1 往下讲，**停在哪一层，真实水平就在哪一层**。

## 四、怎么用这一层

**场景一：面试前专项补洞。** 只翻被问卡住的那个文件，从 L1 讲到 L5，讲不下去就停，第二天重来。

**场景二：日常每天一个知识点。** 一天一个文件，三十分钟：读 L1 到 L3（十五分钟），口述 L4 追问树（十分钟），跑代码验证（五分钟）。

**场景三：模拟面试加压。** 直接说：

```
用 10-deep-dive 里的文件拷问我，从 L1 开始，每答对就追问下一层，答错就停并讲解。
```

## 五、和旧目录的分工

| 目录 | 定位 | 什么时候用 |
|---|---|---|
| [01-js](../01-js/JS核心八股.md)、[03-java](../03-java/Java基础与并发.md) 等 | 广度：一章过完一个领域，每题六十秒 | 第一轮打基础、面试前三天扫盲 |
| 10-deep-dive（本目录） | 深度：一个知识点一个文件，追到最底层 | 第二轮补洞、被追问时、面试前一天挑重点 |

> 顺序建议：先广度保证不翻车，再深度保证能接追问。
