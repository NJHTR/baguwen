# 集合体系（Collection Framework）

> 面试权重：5/5　｜　追问深度：**L5（`System.arraycopy` intrinsic + 内存可见性）**
> 一句话定位：集合题看起来是「背 API」，实际考的是**扩容策略、fail-fast 的计数器、写时复制的可见性**。面试官问「ArrayList 和 LinkedList 怎么选」，答完对比表后真正的追问是「扩容 1.5 倍为什么」「遍历删元素为什么有时不抛异常」。

**本文件用法**：从 L1 往下读，每读完一层合上书自问自答。**停在答不出的那一层，就是你的真实水平线。**

## L1 一句话答案（10 秒能说出口）

`Collection` 分 `List`（有序可重复，数组或链表）、`Set`（去重，靠 hashCode/compare）、`Queue`（队列，Deque 双端）；`Map` 独立成体系。实际选型几乎总是：**ArrayList（查/尾插）+ ArrayDeque（队列）+ HashMap（键值）+ TreeMap/LinkedHashMap（排序/LRU）**，LinkedList 在业务代码里基本不用。

---

## L2 原理层：体系与选型

```
Collection
├─ List   → ArrayList / LinkedList / CopyOnWriteArrayList / Vector
├─ Set    → HashSet / LinkedHashSet / TreeSet
└─ Queue  → ArrayDeque / PriorityQueue / LinkedList（也实现 Deque）
Map（不继承 Collection）→ HashMap / LinkedHashMap / TreeMap / ConcurrentHashMap
```

**选型速查**：

| 需求 | 选 | 复杂度 / 理由 |
|---|---|---|
| 按下标随机读、尾部追加 | `ArrayList` | 读 O(1)、均摊插 O(1) |
| 频繁在头部插入/删除 | `ArrayDeque` | 循环数组，两端 O(1)，比 LinkedList 快 |
| 去重、判存在 | `HashSet` | O(1)，依赖 hashCode+equals |
| 需要按 key 排序 / 范围查询 | `TreeSet` / `TreeMap` | O(log n) |
| 并发键值 | `ConcurrentHashMap` | 不能存 null |

## L3 底层层：扩容、modCount、写时复制

### 3.1 ArrayList：懒初始化 + 1.5 倍扩容

```java
private static final int DEFAULT_CAPACITY = 10;
transient Object[] elementData;                       // 真正存元素；transient 因为自定义序列化

private Object[] grow(int minCapacity) {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity + (oldCapacity >> 1);        // 重点：1.5 倍
    return elementData = Arrays.copyOf(elementData, newCapacity);
}
```

**实测（反射读 `elementData.length`）**：`new ArrayList<>()` 后是 **0**（懒初始化，不是 10）；第 1~10 个 add 后是 10；第 11 个 add 后变 **15**；第 16 个后变 **22**（15×1.5=22.5 取整 22）。

为什么是 1.5 而不是 2：2 倍空间浪费大、且更容易在老年代留下大块待回收区域；1.5 倍是「均摊 O(1) 的复制成本」与「空间利用率」的折中（1.5 倍时总复制量约为 3n，2 倍时约 2n，差距可接受）。

`Arrays.copyOf` 做的事：`new Object[newLength]` + `System.arraycopy` + 返回新数组（原数组被丢弃）。所以扩容是 **O(n) 拷贝 + 一次分配**，这就是「预分配容量」有价值的原因：`new ArrayList<>(expectedSize)` 可以避免多次扩容。

### 3.2 `size` 与 `capacity` 不是一回事

- `size()`：逻辑元素个数（`elementData[0..size-1]` 有效）。
- `capacity`：数组长度，只能通过反射或 `ensureCapacity` 间接观察。

### 3.3 LinkedList：双向链表 + 折半定位

```java
private static class Node<E> { E item; Node<E> next, prev; }    // 每节点 3 引用 + 对象头
transient Node<E> first, last;                                   // 头尾指针

Node<E> node(int index) {                    // 折半定位：从较近的一端开始走
    // index < (size >> 1) → 从 first 往后；否则从 last 往前
}
```

- `addFirst/addLast/removeFirst/removeLast` 都是 O(1)（改 4 个引用）。
- 每个节点多两个引用 + 对象头，**内存开销是 ArrayList 的 3~4 倍**，且节点分散在堆上，**CPU 缓存不友好**——这就是实践中 ArrayList 全面胜出的真正原因（不是「数组插入慢」）。

### 3.4 fail-fast：`modCount` 与 `expectedModCount`

```java
protected transient int modCount = 0;          // AbstractList：结构性修改次数

// ArrayList.Itr
int expectedModCount = modCount;               // 迭代器创建时的快照
public boolean hasNext() { return cursor != size; }   // 重点：注意是 != 不是 <
public E next() {
    checkForComodification();                  // modCount != expectedModCount → CME
    ...
}
```

**关键细节（实测出来的一层）**：`ArrayList.Itr.hasNext()` 是 `cursor != size`，检查只在 `next()` 里。遍历中删元素时 cursor 已经 +1、size 少 1：删**倒数第二个**元素会让 `cursor == size`，`hasNext()` 直接 false，异常逃过；删**第一个**或**最后一个**都 `cursor != size`，仍会进 `next()` 抛 CME。所以 fail-fast 是「尽力检测（best-effort）」，不能当并发安全保证。

**正确姿势**：用 `Iterator.remove()`（它会把 `expectedModCount` 同步成新的 `modCount`），或 JDK 8+ 的 `list.removeIf(pred)`（ArrayList 内部用 `BitSet` 标记再一次性压缩，O(n)）。

### 3.5 CopyOnWriteArrayList：写时复制

```java
private transient volatile Object[] array;     // 重点：volatile：安全发布新数组
public boolean add(E e) {
    synchronized (lock) {
        Object[] es = array;
        int len = es.length;
        es = Arrays.copyOf(es, len + 1);       // 复制整份
        es[len] = e;
        array = es;                            // 原子替换引用
        return true;
    }
}
```

- 迭代器持有的是**创建时的数组快照**，所以遍历中增删不会 CME（实测：for-each 里 `remove` 不抛，且遍历的是旧数据）。
- 代价：每次写都复制整个数组（O(n) 内存 + 时间），且**读可能读到旧值**（最终一致，不保证实时）。

### 3.6 几个「视图」坑

| 写法 | 返回类型 | 坑 |
|---|---|---|
| `Arrays.asList(1,2,3)` | `Arrays$ArrayList`（固定大小） | `add/remove` 抛 `UnsupportedOperationException`；`set` 可以，会**改原数组** |
| `List.of(1,2,3)` | `ImmutableCollections.ListN` | 完全不可变，**连 null 都不允许** |
| `list.subList(1,3)` | `ArrayList$SubList`（视图） | 不是拷贝；对原 list 做结构性修改 → 视图上任何操作抛 CME |
| `Collections.unmodifiableList(list)` | 包装器 | 只是禁止通过包装器改，**原 list 仍能改，且改动可见** |

## L4 追问树（面试官一路往下问，你能撑到第几层？）

> 规则：从上往下问。**第 1-3 层是应届生必备，第 4-6 层拉开差距，第 7 层以后是加分。**

### 第 1 层｜ArrayList 和 LinkedList 怎么选？
**答**：99% 场景选 ArrayList：随机读 O(1)、尾部追加均摊 O(1)、内存连续缓存友好。LinkedList 只在「已经持有节点引用做头尾增删」时才 O(1)，但它的 `get` 是 O(n)、每节点多两个引用、缓存不友好，所以业务代码里基本不用。需要队列/栈用 `ArrayDeque`，它不是 LinkedList，但两头操作都是 O(1) 且更快。

### 第 2 层｜ArrayList 扩容为什么是 1.5 倍？
**答**：`newCapacity = oldCapacity + (oldCapacity >> 1)`。1.5 倍兼顾均摊性能与空间：2 倍浪费空间更大、且大数组更难回收；1.5 倍下总复制量约 3n（几何级数求和），仍是均摊 O(1)。另外 1.5 倍在扩容时更容易复用相邻空闲内存（大数组分配压力小些），不过这一条是工程经验，不是源码保证。

### 第 3 层｜扩容时 `Arrays.copyOf` 到底做了什么？为什么说它是 O(n)？
**答**：`Arrays.copyOf` = `new Object[newCap]`（分配新数组）+ `System.arraycopy`（批量复制）+ 返回新引用。`System.arraycopy` 是 **native + intrinsic**，C2 会把它编译成类似 `rep movs`/AVX 的批量内存拷贝，比 Java 循环快，但复杂度仍是 O(n)——复制 n 个引用，n 越大越慢。所以「已知大小时一定要 `new ArrayList<>(size)`」。

### 第 4 层｜fail-fast 是怎么实现的？
**答**：`AbstractList` 里有 `modCount`，每次结构性修改（add/remove/clear）自增；迭代器创建时记下 `expectedModCount = modCount`，每次 `next()` 前比较一次，不等就抛 `ConcurrentModificationException`。它检测的是「迭代器视角之外的修改」，不是真正的并发。

### 第 5 层｜遍历时删元素，什么时候抛 CME、什么时候不抛？
**答**：`hasNext()` 是 `cursor != size`，检查只在 `next()` 里做。删掉**倒数第二个**元素时 `cursor` 恰好等于新 size，`hasNext()` 返回 false、`next()` 不被调用，异常就逃过；而删**第一个**或**最后一个**，`cursor` 与新 size 不等，仍会进 `next()` 抛 CME（三种情况我都实测过）。所以 fail-fast 是**尽力检测**，不能当并发安全保证。**这是能问住大多数候选人的一层。**

### 第 6 层｜遍历中删除元素的正确做法？
**答**：用 `Iterator.remove()`（它会把 `expectedModCount` 同步成新的 `modCount`）；JDK 8+ 更推荐 `list.removeIf(predicate)`（ArrayList 里用 `BitSet` 标记再一次性压缩，O(n)）。`for (X x : list) list.remove(x)` 是典型的错误写法。

### 第 7 层｜CopyOnWriteArrayList 为什么边遍历边删不抛异常？代价是什么？
**答**：迭代器拿到的是**数组快照**（`COWIterator` 持有旧数组引用），遍历期间原数组被替换成新数组，但迭代器看不到，所以不 CME，也不会抛。代价：每次写都 `Arrays.copyOf` 整个数组（O(n) 时间与内存），写多时性能崩塌；且读是最终一致，可能读到旧值。所以只适合读多写极少、能容忍短暂不一致的场景。

### 第 8 层｜ArrayList 线程不安全体现在哪？
**答**：三个地方：① `add` 时 `elementData[size++] = e` 不是原子操作，两个线程可能写同一个下标或丢元素；② 扩容期间别的线程读到旧数组（引用替换不是原子的可见性问题，其实是数组引用未同步导致读旧）；③ `modCount` 自增竞争。修法：`Collections.synchronizedList`（一把大锁）或 `CopyOnWriteArrayList`（读多写少）、或干脆自己控制不共享。

### 第 9 层｜`new ArrayList<>()` 和 `new ArrayList<>(100)` 有什么区别？
**答**：无参构造用共享的空数组（`DEFAULTCAPACITY_EMPTY_ELEMENTDATA`），**第一次 add 才分配到 10**；传 100 则直接分配 100 的数组。区别在扩容次数：装 100 个元素时，前者会经历 10→15→22→33→49→73→109 共 6 次扩容拷贝，后者 0 次。所以能预估大小时一定传初始容量。

### 第 10 层（终局）｜`System.arraycopy` 和 COW 的「安全发布」到 CPU 层是什么？
**答**：`System.arraycopy` 在 HotSpot 里是 intrinsic，C2 编译后是 `rep movsq`/AVX 批量搬移，走 L1/L2 缓存行；长度小时还会内联成几条 `mov`。COW 的 `array` 字段是 `volatile`，写操作在 x86 上是一条 `mov` + `Lock` 前缀（`lock cmpxchg`/`xchg` 形成的内存屏障），保证「新数组内容先写完，再发布引用」，其他线程读到的引用一定指向完整数组——这是 JMM 的 happens-before 在硬件上的落地。换句话说，COW 的正确性一半靠复制、一半靠 volatile 的发布语义，缺一不可。

## L5 名词拆解表（"每个名词都拆开"）

| 名词 | 是什么 | 为什么存在 | 面试追问点 |
|---|---|---|---|
| `elementData` | ArrayList 的底层数组 | 连续内存、下标寻址 | 为什么声明成 `transient`（自己实现序列化，省空间） |
| `size` vs `capacity` | 逻辑长度 vs 数组长度 | 区分有效元素与预留空间 | `new ArrayList<>(100)` 的 size 是 0 |
| `DEFAULT_CAPACITY` | 10 | 首次 add 的默认分配 | 为什么是懒初始化到 10 |
| `grow` | 扩容方法 | 1.5 倍 + 上限保护 | `MAX_ARRAY_SIZE = Integer.MAX_VALUE - 8` 为什么减 8 |
| `Arrays.copyOf` | 新数组 + `System.arraycopy` | 扩容/复制 | 是浅拷贝，元素引用复用 |
| `modCount` | 结构性修改计数 | fail-fast 检测 | 哪些操作会自增（add/remove/clear，set 不会） |
| `expectedModCount` | 迭代器创建时的 modCount 快照 | 判断是否被外部修改 | 为什么 `hasNext` 不检查 |
| fail-fast / fail-safe | 快速失败 / 快照遍历 | 尽早暴露并发 bug | 谁不抛、为什么仍不安全 |
| `COWIterator` | COW 的迭代器，持有数组快照 | 遍历不加锁 | 迭代期间看不到新元素 |
| `Node<E>` | LinkedList 节点（item/next/prev） | 双向链表 O(1) 头尾操作 | 内存放大 3~4 倍 |
| `ArrayDeque` | 循环数组双端队列 | 栈/队列首选 | 为什么不推荐用 LinkedList 当队列 |

## 代码验证（`CollectionProbe.java`，JDK 17 编译运行通过）

```java
import java.lang.reflect.Field;
import java.util.*;
import java.util.concurrent.CopyOnWriteArrayList;

public class CollectionProbe {
    static int capOf(ArrayList<?> l) throws Exception {
        Field f = ArrayList.class.getDeclaredField("elementData");
        f.setAccessible(true);
        return ((Object[]) f.get(l)).length;
    }
    static void del(int target) {                       // 遍历中删除指定元素
        List<Integer> l = new ArrayList<>(List.of(1, 2, 3));
        try { for (Integer i : l) { if (i == target) l.remove(i); } System.out.println("del(" + target + ") 未抛"); }
        catch (ConcurrentModificationException e) { System.out.println("del(" + target + ") → CME"); }
    }
    public static void main(String[] a) throws Exception {
        ArrayList<Integer> l = new ArrayList<>();
        System.out.println("new=" + capOf(l));                              // 0（懒初始化）
        for (int i = 0; i < 10; i++) l.add(i);
        l.add(10);
        System.out.println("11 个元素=" + capOf(l));                         // 15
        while (l.size() < 16) l.add(0);
        System.out.println("16 个元素=" + capOf(l));                         // 22
        del(1);          // 删第一个   → CME（cursor=1, size=2）
        del(3);          // 删最后一个 → CME（cursor=3, size=2）
        del(2);          // 删倒数第二个 → 不抛（cursor=2, size=2）
        List<Integer> c = new ArrayList<>(List.of(1, 2, 3));
        c.removeIf(x -> x == 1);
        System.out.println("removeIf=" + c);                                 // [2, 3]
        List<Integer> cow = new CopyOnWriteArrayList<>(List.of(1, 2, 3));
        for (Integer i : cow) { if (i == 2) cow.remove(i); }
        System.out.println("COW=" + cow);                                    // [1, 3]
    }
}
```

```bash
javac -encoding UTF-8 CollectionProbe.java
java --add-opens java.base/java.util=ALL-UNNAMED CollectionProbe
```

**预期输出**：`0 / 10 / 15 / 22`、`删首元素 → CME`、`删末元素后 size=2（没抛）`、`removeIf 后=[2, 3]`、`COW=[1, 3]`。

## 高频错误（面试官最爱抓的）

| 错误说法 | 正确说法 |
|---|---|
| 「ArrayList 默认容量是 10，构造时就分配」 | 无参构造是空数组，**首次 add** 才分配 10 |
| 「LinkedList 插入删除都是 O(1)」 | 头尾 O(1)，但按 index 插删要先 `node(index)` 定位，O(n) |
| 「fail-fast 保证一定能检测到并发修改」 | 只在 `next()` 检查，删末尾可能逃过检测，是 best-effort |
| 「遍历时不能删元素」 | 用 `Iterator.remove()` 或 `removeIf` 可以 |
| 「CopyOnWriteArrayList 不抛异常所以线程安全」 | 只是迭代安全 + 最终一致，多次写并发仍有竞争 |
| 「`Arrays.asList` 可以 add」 | 固定大小，add/remove 抛 UnsupportedOperationException |
