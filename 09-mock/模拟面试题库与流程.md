## 一、真实面试长什么样（先破除恐惧）

### 全栈岗位的典型流程

| 轮次 | 时长 | 内容 | 权重 |
|---|---|---|---|
| **HR 初筛电话** | 10-15 min | 自我介绍、项目一句话、期望薪资、到岗时间 | 决定有没有下一轮 |
| **技术一面** | 45-60 min | 自我介绍 2min + 项目 15min + 基础八股 20min + 手写/算法 10min + 反问 5min | 决定生死 |
| **技术二面** | 45-60 min | 项目深挖 20min + 场景设计 15min + 八股 10min + 反问 | 决定职级与薪资 |
| **主管/交叉面** | 30-45 min | 项目真实性、工程素养、协作、学习能力 | 决定愿不愿意要你 |
| **HR 终面** | 20-30 min | 稳定性、价值观、薪资谈判 | 决定发不发 offer |

### 一面的时间分配（最重要的一轮）

```
00:00-02:00  自我介绍
02:00-17:00  项目（1-2 个，深挖）
17:00-37:00  基础八股（顺着项目或随机抽）
37:00-47:00  手写题 / LeetCode 简单-中等
47:00-52:00  你有什么想问我的
```

> **关键认知**：一面 52 分钟里，"能提前准备到 90%" 的是自我介绍、项目、手写、反问这 40 分钟。**别在冷门八股上焦虑，先把这 40 分钟练到滚瓜烂熟。**

## 二、怎么和我做模拟面试（3 种模式）

### 模式 A：完整仿真面（推荐，每周 1 次）
直接对我说：

```
开始一场完整模拟面试，我投的是校招/初级全栈（Java + Vue）。
按真实一面流程：自我介绍 → 项目深挖 → 八股 → 手写题 → 反问。
每题问完等我回答再追问，追问 1-2 层。最后给百分制评分和失分复盘。
不要提前告诉我答案。
```

### 模式 B：专项突击（每次 20 分钟，聚焦一块）
```
专项模拟：只问 JS 核心八股，从我学过的范围随机抽 10 题，
每题我答完你打分（0-5 分）并指出漏掉的关键词。最后汇总我的薄弱点。
```

把 "JS 核心八股" 换成：`Vue3 原理` / `Java 集合` / `Spring` / `MySQL` / `Redis` / `HTTP` / `手写题` / `项目追问` / `HR 面`。

### 模式 C：压力追问（针对项目，最有用）
```
用压力面试风格追问我的项目，我说「项目名/技术栈/我负责的模块」后，
你连续追问 10 层，模拟面试官找破绽。我卡住就停，指出为什么卡。
```
> 这个模式专治"项目讲不深"。第 3 层追问开始，你会明显感到吃力，那就是你真正要补的地方。

## 三、题库：自我介绍与项目（必练）

### 3.1 自我介绍（背到能条件反射）

**90 秒骨架**：
```
① 身份（10s）：面试官好，我是 XX，XX 大学计算机专业 2026 届应届生。
② 技术栈（20s）：主栈 Java + Spring Boot 后端，前端能独立用 Vue3 完成从 0 到 1。
   熟悉 MySQL、Redis，了解 JVM 与并发。
③ 最强项目（40s）：做过一个 XX 项目，我负责 XX 模块，其中我解决最难的
   问题是 XX，用了 XX 方案，效果是 XX。
④ 求职动机（15s）：看重贵司的 XX，我希望能在这个方向深入。
⑤ 收尾（5s）：以上是我的基本情况。
```

**错误：反例**：「我叫 XX，平时喜欢打游戏和看视频，性格开朗……」— 全是无效信息。
**正确：正例**：每一句都指向"我能胜任这个岗位"。

### 3.2 项目必问题（配合追问清单使用）

1. 用 3 分钟讲一下你最有成就感的项目。
2. 这个项目里最难的模块是哪个？难点在哪？
3. 你刚才提到用了 XX，为什么不用 YY？
4. 这个功能的数据流是怎样的？（前端点击 → 接口 → 服务 → 数据库）
5. 如果用户量涨 100 倍，这个项目哪里会先崩？
6. 项目里有什么是你现在回头看会重新设计的？
7. 团队分工怎么做的？有冲突吗？
8. 讲一个你排查线上/联调 bug 的过程。

## 八、评分表（每场模拟面试后填）

> 百分制。目标：连续 3 场 85+ 就可以开始真实投递。

| 维度 | 权重 | 评分标准 | 得分 |
|---|---|---|---|
| **自我介绍** | 10 | 90 秒内讲完，信息有效，不背稿感 | /10 |
| **项目表达** | 30 | 有 STAR/问题驱动结构、细节具体、有数据、能主动引导 | /30 |
| **项目追问防守** | 15 | 10 层追问扛住 7 层以上，卡住时知道怎么接（不是硬编） | /15 |
| **基础八股** | 20 | 10 题答对 8 题以上，有「一句话答案」意识 | /20 |
| **手写/算法** | 15 | 能写出可运行代码，边界条件考虑，会讲复杂度 | /15 |
| **表达与节奏** | 5 | 语速稳、不冷场、不懂会反问不会硬编 | /5 |
| **反问环节** | 5 | 问了有价值的问题（团队/技术/成长），不是"没有问题了" | /5 |

### 失分判定线
- **< 60 分**：某块存在硬伤（项目讲不清 / 八股大面积空白）→ 补那一块
- **60-75 分**：都会但不够深 → 加强追问防守 + 60 秒版熟练度
- **75-85 分**：比较稳 → 补细节数据、练引导节奏
- **> 85 分**：可以真实投递

## 十、答题通识（适用于所有问题）

### 万能答题结构
```
① 先给结论（一句话答案，10-20 秒）
② 再展开（2-3 个分点，每点一句话 + 可选例子）
③ 主动补边界（"不过要注意……" / "这种情况例外……"）
④ 收尾（"以上就是我的理解" / 或反问是否需要展开）
```

### 三种情况的应对

| 情况 | 应对 |
|---|---|
| **完全不会** | 「这块我掌握得不深，我的理解是……（说出你知道的部分），可能不准确，您能指点一下吗？」— 展示诚实 + 部分理解 |
| **半会半不会** | 「我确定的是 A，不太确定 B，我推测 B 可能是因为……，不确定对不对。」— 展示思考过程 |
| **被追问到顶不住** | 「这个层次的实现我没深入看过源码，但我可以说说从设计角度的理解……」— 换维度而不是硬编 |

### 三条红线
1. **绝不硬编**：编一个错的技术细节，比说"不会"扣分更狠（面试官会当场判断诚信问题）
2. **绝不冷场超过 5 秒**：不会就立刻走"我的理解是"或请提示
3. **绝不说"我没问题了"**：反问环节是加分项，至少准备 3 个
