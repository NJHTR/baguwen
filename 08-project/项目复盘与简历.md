# 项目复盘与简历包装

> 面试权重：5/5（项目是面试的 50%，比八股更重要）
> 适用场景：每一场技术面的开场 10-20 分钟都在问项目
> 建议投入：3 天（做完这项工作，面试通过率提升最明显）

---

## 一、为什么项目是最高优先级

面试官的判断逻辑其实很简单：

```
八股答得好 → "这人背过书" → 可能是个包装过的
项目讲得好 → "这人真干过活" → 才是靠谱的候选人
```

**八股决定你会不会被刷，项目决定你会不会被要。**

应届生的项目有个天然劣势：业务简单、用户量小、技术不复杂。但这不代表没得讲——
面试官知道你是应届生，他要看的不是"你做过双十一"，而是：

| 面试官真正在考察 | 你要展示的 |
|---|---|
| 这活是不是你自己干的 | 能说出实现细节、踩过的具体坑 |
| 你有没有思考 | 能说出"为什么这么做"，而不是"教程就这么写" |
| 你遇到问题怎么办 | 有一个完整的"问题 → 排查 → 解决 → 验证"故事 |
| 你懂不懂边界 | 能承认局限，说出"如果要更好我会怎么改" |

> **一句话**：应届项目的胜负手不是"项目多牛"，而是 **"细节密度"** ——你讲得越具体，越可信。

## 三、项目的标准讲法：STAR + 一个变体

### 版本 1：STAR（适合"介绍一下项目"）

```
S 情境（20 秒）：这个项目是什么、给谁用、为什么要做
T 任务（20 秒）：我在里面负责什么、目标是什么
A 行动（90 秒）：我具体怎么做的 —— 这里要占 60% 时间，讲 2-3 个技术决策
R 结果（30 秒）：做成了什么、数据怎样、我学到什么
```

### 版本 2：问题驱动（强烈推荐，更适合应届生）

应届项目业务价值有限，讲"我解决了什么问题"比讲"我做了什么功能"高级得多：

```
1. 背景一句带过（10 秒）
2. 抛出 1 个具体技术难题（20 秒）：
   "项目上线前压测发现，商品详情页 QPS 到 200 就超时。"
3. 我怎么排查的（30 秒）：
   "先看日志定位到是每次都查 3 张表做聚合，然后 explain 发现没走索引……"
4. 我怎么解决的（40 秒）：
   "加了联合索引 + Redis 缓存商品详情，缓存 key 带版本号，更新时删缓存。"
5. 结果（20 秒）：
   "QPS 到 800，P99 从 1200ms 降到 80ms。"
6. 反思（20 秒）：
   "后来发现缓存击穿在热点商品上还会出现，应该加互斥锁或逻辑过期。"
```

**为什么版本 2 更好**：
- 有"问题 → 排查 → 解决 → 验证"的完整闭环，这是真实干活的人才有的叙事
- 天然引出八股（索引、缓存、并发），面试官会顺着往下问，**你就掌握了面试节奏**
- 最后一句反思，显得你有复盘意识

> **实操建议**：准备 **3 分钟版**（版本 2 用 1 个难题）+ **10 分钟版**（版本 2 用 2-3 个难题串起来）。

## 四、亮点包装公式

把你做过的事，套这个公式改成"简历语言"：

```
【技术手段】+【解决的具体问题】+【可量化结果】
```

### 改造对照表

| 原始描述（学生腔） | 包装后（简历语言） |
|---|---|
| 用 Redis 做了缓存 | 针对商品详情页读多写少（读写比 20:1），引入 Redis 缓存并设计「版本号 + 随机过期」防击穿，接口 P99 从 1200ms 降至 80ms |
| 实现了登录注册 | 基于 Spring Security + JWT 实现无状态鉴权，配合 Redis 存储 token 黑名单支持主动登出，解决集群部署下 session 不共享问题 |
| 写了订单模块 | 设计订单状态机（待支付/已支付/已取消/已完成），用 Redis 分布式锁 + 数据库唯一索引双重保证下单幂等，压测 500 并发无重复订单 |
| 做了图片上传 | 改为前端直传对象存储 + 后端签名校验，绕过应用服务器带宽瓶颈，单图上传耗时从 2.3s 降至 400ms |
| 用了 Vue3 写前端 | 基于 Vue3 组合式 API 抽离 12 个业务 composable，复用率 60%；路由级懒加载 + 组件按需引入，首屏体积从 1.8MB 降至 620KB |

### 三条红线
1. **不许编造没做过的技术**——面试官一问细节就穿帮，代价是整场面试作废
2. **不许写"参与"、"协助"**——应届简历上每个模块都该是"我负责"
3. **不许没有数字**——没有精确数据就用合理估算，但要能解释估算依据

## 五、追问防守清单（25 问，务必逐条准备）

> 面试官问项目，本质是在做**真实性验证**。下面每一条都要能 30 秒内答出。

### A. 项目背景类（5 问）
1. 这个项目解决什么问题？目标用户是谁？
2. 为什么用这套技术栈？换成别的行不行？
3. 项目是你独立做的还是团队做的？你具体负责哪部分？
4. 有真实用户吗？有多少？
5. 项目做了多久？中间有没有中断？

### B. 技术选型类（5 问）
6. 为什么用 Vue3 不用 Vue2 / React？
7. 为什么用 MyBatis-Plus 不用 JPA？
8. 为什么选 Redis 而不是本地缓存？
9. 前端状态管理为什么用 Pinia？小项目有必要吗？
10. 数据库为什么用 MySQL？如果数据量涨 100 倍怎么办？

### C. 实现细节类（8 问，**最容易翻车，重点准备**）
11. 登录鉴权具体怎么实现的？token 存哪？过期怎么处理？
12. 下单流程说一遍，从点击到入库经过哪些步骤？
13. 你说的缓存，key 怎么设计的？什么时候失效？
14. 你说的分布式锁，用的什么命令？锁超时了怎么办？
15. 订单超时未支付怎么自动取消？
16. 图片上传的完整链路说一下，签名怎么算的？
17. 分页查询怎么写的？深分页怎么优化？
18. 前端这个页面数据怎么来的？请求了几次？有没有做防抖？

### D. 问题与优化类（5 问，**最能加分**）
19. 项目里遇到最大的坑是什么？怎么解决的？
20. 有没有做过性能优化？优化前后数据？
21. 项目有什么不足？如果重做你会怎么改？
22. 有没有考虑过并发问题？在哪里？
23. 上线后出过 bug 吗？怎么定位的？

### E. 反思与延伸类（2 问）
24. 这个项目你学到最多的是什么？
25. 如果现在让你加一个 XX 功能，你会怎么设计？

> **准备方法**：每条写下答案关键词（不是全文），然后找人/找我模拟提问。答不顺的标 `待确认`，重点练。

## 六、应届生项目的补强方案（没亮点怎么办）

如果项目确实很单薄，用下面这些"低成本高回报"的改造，让它在面试里立得住：

| 现状 | 补强动作 | 面试话术 |
|---|---|---|
| 项目没人用 | 做一次压测（JMeter/wrk），拿数据说话 | 「我用 JMeter 压到 500 并发，发现瓶颈在……优化后 QPS 提升 3 倍」 |
| 业务太简单 | 给核心接口加缓存 + 说明命中率 | 「详情页读多写少，加缓存后 DB 压力下降 70%」 |
| 没有并发场景 | 人为造一个并发点（库存/领券） | 「我刻意设计了限量领券场景来练并发控制」 |
| 没有工程化 | 接入日志、统一异常、参数校验、Swagger | 「我做了统一响应封装和全局异常处理，减少 40% 重复代码」 |
| 完全跟教程 | 在教程项目上加 1 个原创模块 | 「在基础版上我自己加了 XX 功能，设计时遇到 X 问题……」 |
| 没部署过 | 用 Docker 部署到云服务器 | 「用 Docker Compose 部署了完整环境，配了 Nginx 反向代理」 |

> **最推荐的两个**：① **压测并给出优化前后数据** ② **给项目加一个自己设计的原创模块**。这两个改造成本低，但直接解决"项目没内容可讲"的问题。

### 简历的 6 个常见坑

| 坑 | 症状 | 改法 |
|---|---|---|
| 写"精通" | 应届写"精通 Java" | 改成"熟练"，面试官会拿"精通"标准考你 |
| 堆名词 | 技能栏列 30 个技术 | 只列你真会被问的，留 10-15 个 |
| 无数字 | "提升了系统性能" | 加前后对比数据 |
| 一页放不下 | 密密麻麻 | 删无关课程、删学生会经历 |
| 与 JD 不对齐 | 投 Java 岗简历突出前端 | 按 JD 调整技能和项目的顺序 |
| 错别字/格式乱 | 中英文混排不统一 | 导出 PDF 检查一遍 |

## 八、行为面试 / HR 面的 10 个必备答案

| 问题 | 答题骨架 |
|---|---|
| 自我介绍 | 身份 + 技术栈 + 1 个最强项目 + 求职动机，**控制在 90 秒** |
| 你最大的优点 | 选一个和岗位强相关的，配一个项目例子证明 |
| 你最大的缺点 | 选真实但不致命的（如"过于关注细节导致前期进度慢，现在会先做 MVP 再打磨"）+ 改进动作 |
| 为什么选我们公司 | 三句话：业务我感兴趣 + 技术栈匹配 + 我能贡献什么 |
| 职业规划 | 1 年站稳 + 2-3 年深耕一个方向（给具体方向，别说"当架构师"） |
| 遇到过最大的困难 | 用 STAR，必须讲解决过程和结果 |
| 和同事意见冲突怎么办 | 用数据/小实验说话，而不是"谁级别高听谁" |
| 能接受加班吗 | 表达理解业务节奏 + 强调效率优先，别硬刚也别谄媚 |
| 你还有什么问题问我们 | 准备 3 个：团队技术栈、新人培养、这个岗位的挑战是什么 |
| 期望薪资 | 应届给区间 + 结合城市，说"更看重成长"，但不要不敢说数字 |
